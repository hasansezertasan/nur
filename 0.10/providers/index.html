Provider register#

This section is the permanent record of every task-runner format nur has considered: what it is, how it was evaluated, what was decided and why. It exists so the reasoning never depends on GitHub issues. The selection rule is ADR 0005: a format is accepted when it passes three gates (safe listing, a faithful run command, an honest subset). Popularity is not a gate.

nur is for developers and agents working in a terminal, so the goal is to cover every format that can be supported honestly.

The register began as issue #78; its content is preserved in Origin of the register.

How to read the register#

State

Meaning

Implemented

A provider ships. Evaluation kept in implemented.

Accepted

Passes all three gates; implementation not yet done. See candidates.

Pending

Not yet accepted: a gate is unresolved or evaluation is incomplete. See candidates.

Declined

Fails a gate. Reason and revisit trigger in declined.

Research

A cross-cutting investigation with measured results, under research.

The eight providers that predate the register (npm, make, pdm, poe, just, Taskfile, mise, xc) were backfilled in implemented. ADR 0005 still says that backfilling is open work: ADRs are immutable once accepted, so this page is where its completion is recorded.

Add a register entry, using the evaluation template, before opening an implementation issue. A provider PR updates its entry in the same change.
