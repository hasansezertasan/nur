nur.core.shell.quote_for_cmd(argument)[source]#

Quote one argument for cmd.exe and the MSVC argv parser, only if needed.

Plain tokens stay bare, since cmd.exe built-ins such as echo print quotes verbatim. Anything with whitespace, quotes, or cmd.exe operators such as & or > is double-quoted so it stays one literal token. cmd.exe expands %NAME% even inside quotes, so each % is emitted as ^% between quoted pieces: the caret keeps it literal, and the quote characters around it stop the text from naming a real variable.

nur.core.providers.nox.parse_noxfile(text, source_file='noxfile.py')[source]#

Extract nox sessions from text by AST parsing, never importing it.

nox --list imports and executes noxfile.py to build its registry, so discovery reads @nox.session-decorated functions from the syntax tree instead. It only trusts straight-line noxfiles: module code may use imports, plain statements (assignment, del, expression, pass, def, class), and if/try blocks made of those, where a raise ends its branch. Sessions register only from top-level def statements. Anything else (loops, with, match, assert, except*, a star import from another module) makes nox’s registry depend on control flow nur does not follow, so nothing is listed rather than a session nox may not register. python=[...] and @nox.parametrize variants are surfaced under their base name (nox -s <name> still runs every variant).

Parameters:

  • source_file (str)

Return type:

nur.core.providers.nx.parse_nx(text, source_file='nx.json')[source]#

Parse a workspace root’s nx.json text without executing anything.

Deliberately does NOT run nx show projects to enumerate tasks: that loads Nx plugins and infers targets, which can run repository-controlled code during discovery. Reading the targetDefaults keys directly is safe, at the cost of missing per-project-only targets. Only literal target names become tasks: executor keys (@nx/js:tsc) and globs (e2e-ci--**/**) cannot be run via nx run-many -t and are skipped, while array-form defaults (filtered entries for one target) are accepted like plain objects. Discover Apache Ant targets by parsing build.xml, without running Ant.

nur.core.providers.ant.parse_build_xml(text, source_file='build.xml')[source]#

Extract runnable entry names from build.xml without executing anything.

Deliberately does NOT shell out to ant -p: the file is declarative XML, so <target name=...> attributes can be read directly and a task body (a sequence of XML tasks, not shell commands) never runs during discovery. <extension-point name=...> entries are listed the same way: they are target-like states with a name and an optional description, each running as ant <name>. Descriptions come from the description attribute; every entry is listed, including ones without a description (which ant -p hides as internal). Names are kept verbatim — Ant permits spaces in target names and argv_base passes the name as a single token, so normalizing would change the target’s identity. Only a missing name or an actually empty one is skipped (Ant rejects the latter); anything else, including whitespace-only names, stays listed exactly as Ant accepts it. Names beginning with a hyphen are skipped: Ant parses such arguments as options, so they cannot run via ant <name> (the conventional internal-target form); the check mirrors Ant’s own startsWith("-") on the same verbatim token, so padded variants (`` -init ) stay listed. Only core-namespace ``<target>/<extension-point> elements count: other namespaces are ordinary task/type uses, not entry points. Documents whose root is not an Ant <project> element are skipped: Ant rejects them before installing any target. Task bodies stay opaque, so definition is empty. Imported/included build files, macrodef-defined behaviour, if/unless conditions, depends ordering, and ${property} interpolation are not resolved; names are left literal. Parser errors skip the file. Files with a <!DOCTYPE> declaration are skipped as well: it is the only carrier of <!ENTITY> definitions, whose expansion is unbounded, and genuine Ant build files never need one. Detection is an expat pre-scan that aborts at the first declaration, so no entity is ever expanded during discovery. Results are syntactic task candidates, not a promise that Ant will accept or successfully execute each target.

Byte input is preferred: ElementTree honours the XML encoding declaration only for bytes; a str carrying one is skipped as unparsable. Byte input in an encoding outside the stdlib’s native set (multibyte ones like Shift_JIS, UTF-32, or EBCDIC variants, which Ant accepts) is transcoded to UTF-8 first.

Parameters:

  • text (str | bytes)

  • source_file (str)

Return type:

list[Task]

Discover workspace member scripts without executing anything.

Parse mask commands out of a maskfile text without executing anything.
